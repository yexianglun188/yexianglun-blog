## 四、改进清单（按优先级，含工作量）

### P0 — 必修，半天到 1 天

1. **清掉原作者身份残留（5 处）**  
   `siteConfig.url` 改成自己的域名/穿透地址 → `next.config.ts` 图片白名单换成自己的 OSS → `config.py` CORS 去掉 `boke.hiromu.top` → `projectsData.ts` 换成自己的项目 → README 链接替换。
   > 改 `next.config.ts` 后必须重新 `next build`（生产模式）。
2. **补文章详情页目录 TOC**  
   在 `app/posts/[slug]/page.tsx` 里从渲染后的 Markdown 抽 `h2/h3` → 生成锚点 → 右侧/左侧悬浮目录 + 滚动高亮当前章节。约 80~120 行，纯前端，不动后端。
3. **加 `sitemap.xml` + `robots.txt`**  
   新增 `app/sitemap.ts`（拉已发布文章 + 静态路由）和 `app/robots.ts`。各 20 行左右，配合已有 `app/feed/route.ts` 把 SEO 补齐。

### P1 — 加分，3~5 天

1. **后台用户管理页**  
   后端 `api/identity.py` 加 `GET /admin/users`（列表）、`PATCH /admin/users/{id}`（禁用）、`DELETE`；后台新增 `views/user/` + `router/modules/user.ts`。解决「随机注册账号管不了」的问题，也是账号体系的闭环。
2. **评论楼中楼**  
   后端返回时把 `parent_id` 组装成树（一次查询 + 内存组装即可），`PostComments.tsx` 加「回复」按钮和二级缩进样式。数据层已就绪，改动不大。
3. **文章 PV / 点赞落地**  
   文章详情接口命中时 `views += 1`；前台加点赞按钮调 `POST /api/posts/{id}/like`（同 IP/用户去重）。字段已存在。
4. **站内全文搜索页**  
   后端 `GET /api/posts/search?q=`（标题 + 摘要 + 正文模糊匹配），前台新增 `/search` 页，首页 `SearchBar` 跳转过去。

### P2 — 锦上添花，可选

1. 文章详情页 3D 倾斜（对齐视频观感）
2. 归档页按月份分组 + 标签云页
3. 后台仪表盘加「近 7 天访客趋势」折线图（数据已在 `visitor` 表）
4. 评论邮件/站内通知（需要发信服务，成本高，不建议）
5. Docker Compose 一键起（答辩演示环境加分，但本地已能跑，性价比一般）

## 五、时间成本建议（结合专升本主线）

考试复习是主线，建议**只做 P0 全部 + P1 的第 4、5 项**，总工期控制在 **5~7 天**：

- P0 三项做完，功能上就**完全追平原作者**，且身份信息干净、SEO 完整 —— 答辩/演示没有任何明显短板。
- P1 第 4 项（用户管理）让账号体系闭环，第 5 项（楼中楼）是**原作者也没有**的差异化亮点，写在简历/素质材料里最值。
- P2 除非时间富余，否则不建议碰；工具箱 36+18 和 garden 18 个子站已经足够撑「功能丰富」的印象。
